
## 项目结构

**驱动层 (drivers)** — 9个模块：电源、ADC、风扇、按键、LED、蜂鸣器、NVS、看门狗，纯硬件抽象，无业务逻辑

**服务层 (services)** — 5个模块：
- 电源管理：6路时序控制 + 三级保护（告警/降额/切断）+ 掉电检测
- 状态监测：复合滤波 + 电能统计 + PID智能温控
- MQTT通信：定时上报 + 远程命令 + 遗嘱消息
- Modbus-RTU：标准从站协议 + CRC16校验
- OTA升级：MD5校验 + 试运行期 + 自动回滚

**UI层 (ui)** — 8个模块：UI管理器 + 5个功能页面 + LED状态指示 + 蜂鸣器告警

**工具层 (utils)** — 5个模块：统一错误码、日志、CRC16、数字滤波、PID控制器

## 1. 项目概述

### 1.1 项目简介
本系统是基于 ESP32-S3 + MicroPython 开发的异构算力板卡智能电源管理解决方案，专为多域异构计算平台设计，提供6路独立电源域的精细化管控、实时状态监测、三级保护机制和多种通信接口。

### 1.2 核心功能
- **6路独立电源域控制**：支持独立上下电时序控制，满足FPGA/GPU/MCU等多芯片上电顺序要求
- **三级保护机制**：告警级→降额级→切断级，层层递进保护硬件安全
- **高精度监测**：6路电压、6路电流、3路温度实时采集，复合滤波保证数据稳定
- **智能温控**：PID算法控制风扇转速，温度-转速闭环调节
- **掉电保护**：交流掉电快速检测，大电容支撑下完成数据保存和安全下电
- **双通信接口**：MQTT云端 + Modbus-RTU工业总线，适配不同应用场景
- **OTA远程升级**：支持固件远程升级、MD5校验、试运行期自动回滚
- **本地人机交互**：OLED/LCD显示 + 三按键操作 + LED状态指示 + 蜂鸣器告警

### 1.3 技术栈
| 层次 | 技术 |
|------|------|
| 主控芯片 | ESP32-S3-WROOM-1 |
| 固件平台 | MicroPython v1.20+ |
| UI框架 | LVGL 8.x (可选) |
| 云端协议 | MQTT 3.1.1 |
| 工业总线 | Modbus-RTU (RS485) |
| 存储 | NVS (Non-Volatile Storage) |

## 2. 架构设计

### 2.1 三层解耦架构
系统严格遵循 **驱动层(driver) → 服务层(service) → UI层(ui)** 三层解耦架构，层间依赖只能自上而下，禁止反向调用。

```
┌─────────────────────────────────────────┐
│              UI 层 (ui)                 │
│  页面管理 │ LED指示 │ 蜂鸣器告警        │
└───────────────┬─────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────┐
│           服务层 (services)             │
│  电源管理 │ 状态监测 │ MQTT │ Modbus    │
│              OTA升级                    │
└───────────────┬─────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────┐
│           驱动层 (drivers)              │
│  电源 │ ADC │ 风扇 │ 按键 │ LED        │
│  蜂鸣器 │ NVS │ 看门狗                  │
└─────────────────────────────────────────┘
```

### 2.2 架构优势
1. **职责单一**：每层只负责自己的领域，驱动层只管硬件，服务层只管业务逻辑，UI层只管交互展示
2. **易于测试**：各层可独立单元测试，底层可模拟替换
3. **便于移植**：更换硬件只需修改驱动层，上层业务逻辑无需改动
4. **并行开发**：不同层次可由不同人员并行开发

## 3. 模块原理

### 3.1 电源管理模块
#### 上电时序控制
6路电源域按配置的延迟依次开启，确保FPGA核心先供电、IO后供电等硬件要求。下电时按逆序关闭，避免电流倒灌损坏芯片。

#### 三级保护机制
| 保护等级 | 触发条件 | 动作 | 恢复方式 |
|---------|---------|------|---------|
| 告警级 | 电压偏差≥5%，电流≥80%额定，温度≥70℃ | 点亮告警灯，上报告警信息，蜂鸣器提示 | 参数恢复正常自动解除 |
| 降额级 | 电压偏差≥10%，电流≥90%额定，温度≥80℃ | 关闭非必要电源域（后2路），系统降额运行 | 自动恢复（延迟30秒）或手动 |
| 切断级 | 电压偏差≥15%，电流≥110%额定，温度≥90℃ | 紧急切断所有电源，故障锁存 | 手动复位故障后重新上电 |

所有保护均带消抖滤波，防止瞬时干扰误触发。切断级故障默认锁存，防止故障反复启停损坏设备。

### 3.2 状态监测模块
#### 数据采集与滤波
每路模拟量采用 **复合滤波算法**（滑动平均 + 中值滤波），有效抑制工频干扰和随机噪声，数据稳定可靠。

#### 电能统计
实时计算各电源域功率和总功率，累计电能消耗，数据定期保存到NVS，掉电不丢失。

#### 智能风扇控制
采用 **位置式PID算法** 实现温度闭环控制：
- 温度低于下限（40℃）：风扇停转，静音运行
- 温度在工作区间：PID自动调节占空比
- 温度高于上限（75℃）：风扇全速运行
- 支持转速反馈检测，风扇停转自动告警

### 3.3 通信模块
#### MQTT云端通信
- 标准MQTT 3.1.1协议，支持QoS 0/1
- 遗嘱消息（LWT）：异常离线自动通知服务器
- 定时上报：电压、电流、温度、功率、状态、故障码
- 远程命令：上电、下电、复位故障、参数设置
- 主题规范：`power/{device_id}/data`、`power/{device_id}/cmd`、`power/{device_id}/status`

#### Modbus-RTU工业总线
- 标准Modbus-RTU从站协议，CRC16校验
- 波特率9600，8数据位，1停止位，无校验（可配置）
- 输入寄存器（0x04）：实时监测数据（只读）
- 保持寄存器（0x03/0x06/0x10）：配置参数和控制命令（可读写）

### 3.4 OTA升级模块
- 支持HTTP/HTTPS远程下载固件
- MD5完整性校验，防止固件损坏
- 双分区升级，升级失败不影响原系统
- **试运行机制**：升级后进入试运行期（默认5分钟），运行正常自动确认；异常则自动回滚
- 升级进度实时可查

## 4. 快速上手

### 4.1 硬件准备
- ESP32-S3 开发板（或定制板卡）
- 6路电源控制电路（MOS管/继电器 + 驱动）
- 电压电流采样电路（分压电阻 + 运放 + ACS712等）
- 温度传感器（NTC热敏电阻或DS18B20）
- 4线PWM风扇
- 3个按键、4个LED、无源蜂鸣器
- RS485收发芯片（可选，用于Modbus）

### 4.2 环境搭建
1. **烧录MicroPython固件**
   - 下载 ESP32-S3 对应 MicroPython 固件
   - 使用 esptool 烧录：`esptool.py --chip esp32s3 write_flash 0x0 firmware.bin`

2. **上传项目文件**
   - 使用 mpremote 或 Thonny 将所有文件上传到 ESP32
   - 保持目录结构，config.py 放在 config/ 目录下

3. **修改配置**
   - 编辑 `config/config.py`，根据实际硬件修改引脚定义和参数
   - 配置WiFi和MQTT服务器信息

### 4.3 运行验证
1. 上电后观察串口输出，确认系统启动正常
2. 按MENU键切换页面，验证按键和显示
3. 短按OK键执行上电，检查各电源域是否按时序开启
4. 查看监测页面，确认电压电流温度数据正常
5. 长按OK键执行紧急断电，验证保护功能

### 4.4 首次使用流程
1. 检查硬件接线，确认无误后上电
2. 系统启动，默认待机状态（电源灯慢闪）
3. 短按OK键或发送MQTT命令执行上电
4. 系统按时序开启各电源域，进入运行状态
5. 运行中实时监测各项参数，异常自动触发保护

## 6. 配置说明

所有配置集中在 `config/config.py` 文件中，修改配置即可适配不同硬件，无需改动业务代码。

### 6.1 系统配置 (SYS_CONFIG)
```python
SYS_CONFIG = {
    "device_id": "PWR-001",      # 设备唯一ID
    "fw_version": "v1.0.0",      # 固件版本
    "hw_version": "v1.0",        # 硬件版本
    "serial": "SN2024010001",    # 生产序列号
    "wdt_enable": True,          # 是否启用看门狗
    "wdt_timeout": 30,           # 看门狗超时时间(秒)
}
```

### 6.2 电源配置 (POWER_PIN_CONFIG)
- `control_pins`: 6路电源控制GPIO列表
- `domain_names`: 各电源域名称
- `rated_voltage`: 各电源域额定电压(V)
- `rated_current`: 各电源域额定电流(A)
- `power_on_delays`: 上电延迟列表(ms)
- `power_off_delays`: 下电延迟列表(ms)

### 6.3 保护配置 (PROTECTION_CONFIG)
三级保护阈值，按实际需求调整：
```python
PROTECTION_CONFIG = {
    "warning": {          # 告警级
        "voltage_deviation": 0.05,   # 电压偏差5%
        "current_ratio": 0.8,        # 电流80%额定
        "temp_threshold": 70,        # 温度70℃
    },
    "derate": {           # 降额级
        "voltage_deviation": 0.10,
        "current_ratio": 0.9,
        "temp_threshold": 80,
        "auto_recovery": True,       # 自动恢复
        "recovery_delay_ms": 30000,  # 恢复延迟30秒
    },
    "cutoff": {           # 切断级
        "voltage_deviation": 0.15,
        "current_ratio": 1.1,
        "temp_threshold": 90,
        "latch": True,              # 故障锁存
    },
}
```

### 6.4 通信配置
- **WIFI_CONFIG**: WiFi SSID、密码、连接超时
- **MQTT_CONFIG**: 服务器地址、端口、用户名密码、上报间隔、QoS
- **MODBUS_CONFIG**: 从机地址、波特率、串口引脚

| 0x0001 | 风扇目标温度 | 读写 | 0.1℃，默认550=55.0℃ |
| 0x0002 | 保护等级 | 读写 | 0=禁用,1=告警,2=降额,3=全部 |
| 0x0003 | 控制命令 | 写 | 1=上电,2=下电,3=复位故障 |

## 8. 可靠性设计

### 8.1 三级保护机制
- **分层递进**：告警→降额→切断，给系统留足缓冲空间
- **消抖滤波**：所有保护触发均经过消抖，防止瞬时干扰误动作
- **故障锁存**：严重故障默认锁存，避免反复重启损坏硬件
- **独立硬件**：保护逻辑由MCU独立执行，不依赖上位机或网络

### 8.2 掉电保护
- **快速检测**：输入电压低于阈值立即触发掉电中断
- **大电容支撑**：硬件设计大电容储能，保证MCU继续运行100ms以上
- **紧急保存**：检测到掉电立即保存关键数据到NVS
- **安全下电**：按时序关闭各电源域，避免突然断电损坏芯片

### 8.3 看门狗机制
- 硬件看门狗，超时30秒自动复位
- 主循环定期喂狗，程序跑飞自动重启
- 初始化失败不启动看门狗，便于调试

### 8.4 OTA安全升级
- **双分区设计**：运行分区和升级分区分开，升级失败不影响运行
- **MD5校验**：固件下载完成后校验完整性，损坏则丢弃
- **试运行期**：升级后进入5分钟试运行，运行正常才确认生效
- **自动回滚**：试运行期内异常重启自动回滚到旧版本

### 8.5 数据可靠性
- NVS存储，掉电不丢失
- 关键参数定期保存，异常时数据不丢失
- 电能统计累计保存，支持长期计量

### 8.6 通信可靠性
- MQTT自动重连，网络恢复自动上线
- Modbus CRC校验，数据错误自动丢弃
- 命令执行结果可查询，状态可追溯

## 9. 扩展指南

### 9.1 新增电源域
1. 在 `config.py` 的 `POWER_PIN_CONFIG` 中增加对应引脚和参数
2. 电源驱动会自动适配（遍历所有配置的引脚）
3. 在保护配置中确认阈值是否适用
4. UI页面自动适配，无需修改

### 9.2 新增监测通道
1. 在 `ADC_PIN_CONFIG` 中增加ADC通道配置
2. `adc_driver.py` 中增加对应的校准参数
3. `monitor_service.py` 自动扩展滤波器
4. 监测页面自动显示新增通道

### 9.3 新增通信协议
1. 在 `services/` 目录下新建服务文件
2. 继承现有服务模式，提供 `init()`、`update()`、`deinit()` 接口
3. 在 `main.py` 中初始化并加入主循环调度
4. 通过调用 `power_service` 和 `monitor_service` 获取数据和发送命令

### 9.4 替换显示方案
本项目UI层采用抽象设计，可轻松替换为不同显示方案：
- **OLED (I2C)**：在页面 `draw()` 方法中替换为 ssd1306 驱动调用
- **LCD (SPI)**：替换为 ST7789/ILI9341 等驱动
- **LVGL**：将页面基类改为 LVGL 页面控件，各页面创建对应LVGL对象

### 9.5 自定义保护逻辑
在 `power_service.py` 的 `check_protections()` 方法中可扩展：
- 增加新的保护条件（如功率限制、时间限制）
- 修改保护动作（如发送短信、触发继电器）
- 调整恢复策略

## 10. FAQ

### Q1: 上电后没有反应，串口也没有输出？
**A**: 检查以下几点：
1. 确认ESP32供电正常，3.3V电压稳定
2. 确认烧录了正确的MicroPython固件（ESP32-S3版本）
3. 检查串口波特率，默认115200
4. 确认boot.py和main.py已正确上传

### Q2: 电压电流读数不准，偏差很大？
**A**: 需要进行ADC校准：
1. 用高精度万用表测量实际电压
2. 修改 `config.py` 中 `ADC_PIN_CONFIG` 的 `scale` 和 `offset` 参数
3. 电流采样需注意ACS712的零点偏移，可在零电流时校准offset

### Q3: 保护频繁误触发怎么办？
**A**: 可以从以下方面调整：
1. 适当提高保护阈值，放宽余量
2. 增加消抖计数（修改滤波参数）
3. 检查硬件是否有干扰，增加滤波电容
4. 确认采样电路设计是否正确

### Q4: MQTT连接不上服务器？
**A**: 排查步骤：
1. 确认WiFi配置正确，ESP32能正常联网
2. 检查MQTT服务器地址、端口、账号密码
3. 确认服务器防火墙开放对应端口
4. 查看串口日志，根据错误码定位问题

### Q5: Modbus通信没有响应？
**A**: 检查：
1. 确认RS485接线正确（A-B对应）
2. 确认波特率、数据位、停止位、校验位匹配
3. 确认从机地址设置正确
4. 用示波器查看总线上是否有请求帧

### Q6: 风扇不转或者转速异常？
**A**: 检查：
1. 确认风扇是4线PWM调速风扇
2. 测量PWM引脚是否有波形输出
3. 检查风扇供电是否正常（通常12V）
4. 确认目标温度设置是否过低（低于当前温度则停转）

### Q7: 如何恢复出厂设置？
**A**: 有两种方式：
1. 在设置页面选择"恢复默认"（仅恢复运行参数）
2. 擦除NVS分区：`import esp32; nvs = esp32.NVS('pwr_mgmt'); nvs.erase_all()`

### Q8: OTA升级失败变砖了怎么办？
**A**: 本系统设计了双分区和回滚机制：
1. 升级失败会自动保留原固件，重启后仍运行旧版本
2. 如果试运行期内异常，也会自动回滚
3. 极端情况可通过串口重新烧录固件恢复

### Q9: 最多支持多少路电源域？
**A**: 理论上受GPIO数量限制，ESP32-S3有约40个可用GPIO。软件层面支持任意数量，只需在配置中增加即可。建议单芯片控制不超过16路，过多可考虑IO扩展芯片。

### Q10: 可以同时使用MQTT和Modbus吗？
**A**: 可以，两个通信接口独立工作，互不影响。MQTT走WiFi网络，Modbus走串口总线，可以同时连接云端和本地PLC。
